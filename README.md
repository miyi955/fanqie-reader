# 番茄小说 · 个人书架

在电脑上完整阅读番茄小说（含锁章/VIP 章）。桌面应用形态，多本书统一管理，可按书控制是否抓取最新章节。

> **维护规则**：当前版本（`v2.1.0`）为功能基线。后续迭代必须保证已有功能完整，改完跑 `npm test` 必须全绿。
> 基线清单见 [BASELINE.md](BASELINE.md)，逐条列出全部现有能力，是验收标准也是防止误删功能的检查依据。
>
> **给别人装**：把本目录连同 [SETUP.md](SETUP.md) 一起交出去，对方让 AI 助手读那份文档就能一步步装好。

## 快速开始

**双击桌面上的「番茄小说」图标**（或 `开始.bat`）。

会直接打开一个应用窗口——没有地址栏、没有标签页，就是一个书架应用。背后是一个只监听 `127.0.0.1` 的本地服务，浏览器用 Edge/Chrome 的 `--app` 模式呈现。

关掉窗口后，服务会在空闲 15 分钟后自动退出，不留后台进程。

### 关于开机/重启

不需要装开机自启。重启电脑后直接双击图标即可：服务是按需启动的，图标指向的就是启动入口。

启动流程（约 1 秒）：

1. 启动器拉起一个隐藏窗口的后台进程
2. 后台进程绑定随机本地端口、写好实例记录
3. 浏览器以应用窗口打开书架
4. 启动器确认服务真的能响应后才退出

如果后台进程起不来，启动器会退回到自己直接跑（会留一个最小化的控制台窗口），而不是让你双击了没反应。原因记在 `logs/app.log`。

重复双击不会起第二个服务——探活到已有实例就直接把窗口指过去。重启后 `instance.json` 里的旧记录不会被误连，只有返回正确应用标识的实例才算数。

## 三个核心能力

### 1. 加书

点右上角 **`+ 加书`**：

- 粘贴链接：`https://fanqienovel.com/page/7686168223049337880`
- 或者直接输数字 id
- 不知道 id 就在同一个弹层里搜书名/作者，点「加入」

加进去会自动下载全文、抓封面、生成阅读器。

### 2. 按书控制是否抓最新章节

**每本书封面下方都有一个开关。**

| 状态 | 开关 | 追更时 |
|---|---|---|
| 连载中 | 可开关 | 开着 → 抓新章；关掉 → 跳过 |
| 已完结且已下完 | **锁死关闭** | 永久跳过，不再消耗请求配额 |
| 已完结但缺章 | 仍可开关 | 会补齐缺的章节（不然缺口永远补不上） |

「已完结」是由番茄目录返回的 `isFinished` 判定的。一旦判定完结且本地已完整，就再也不抓——这是你要的效果。

**追更手动触发**：点顶栏 `⟳ 追更` 检查全部书；单本追更在卡片右下角 `⋯` 菜单里。

### 3. 桌面应用

- 桌面快捷方式 + 开始菜单项已生成，图标是应用自己的 ICO
- 快捷方式指向 **你自己装的 node**（nvm 的 `v22.23.4`），不依赖任何特定环境
- 单实例：重复双击不会开第二个，会直接唤起已有窗口
- 无控制台窗口（快捷方式以最小化方式启动）

## 界面

- **封面墙**：等比完整显示，不裁切。封面转 JPEG 后由服务端按需提供
- **筛选**：全部 / 连载中 / 已完结 / 自动追更 / 不追更 / 未下完
- **搜索**：书名或作者，按 `/` 聚焦
- **主题**：日间 / 暖色 / 夜间，`◐` 切换，记在 localStorage
- **右键或 `⋯`**：打开阅读、单独追更、导出 TXT、移出书架

### 移出书架是安全的

不再直接 `unlink` 删除。文件会被 **移动到 `.cache/.trash/<时间戳>/`**，需要时可以手动找回。
（这条是踩坑后加的：早期版本直接删，误操作丢掉过两本书的缓存。）

回收目录只增不减，一本书 5–12 MB。确认不需要找回时，直接删掉 `.cache/.trash/` 整个文件夹即可。

## 阅读器

`books/<bookId>.html`，单文件，可以拷到别的电脑、手机上看。

| 键 | 作用 |
|---|---|
| `←` `→` / `空格` | 上一章 / 下一章 |
| `T` | 收起/展开目录 |
| `/` | 搜索章节标题 |
| `Aa` `+` `−` | 字体切换 / 字号 |
| `◐` | 日间 → 羊皮纸 → 夜间 |

进度、字号、主题存在浏览器 localStorage，每本书独立，下次自动接着看。

## 命令行

桌面版不支持批量操作时用命令行，两边共用同一套核心逻辑（`core.mjs`）。

| 命令 | 作用 |
|---|---|
| `node fanqie.mjs app` | 启动桌面版 |
| `node fanqie.mjs list` | 终端查看书架 |
| `node fanqie.mjs add <id\|链接>` | 加书（下载全文） |
| `node fanqie.mjs search "书名"` | 搜索 |
| `node fanqie.mjs info <id\|链接>` | 看简介和目录 |
| `node fanqie.mjs update` | 追更：所有可追的书 |
| `node fanqie.mjs update <id\|链接>` | 追更：指定一本 |
| `node fanqie.mjs auto <id\|链接> on\|off` | 开关自动追更 |
| `node fanqie.mjs rm <id\|链接>` | 移出书架（进回收目录） |
| `node fanqie.mjs txt <id\|链接>` | 导出 TXT |
| `node fanqie.mjs shelf` | 生成单文件书架页 |

`<id|链接>` 两种都行：`7686168223049337880` 或完整 URL。

### 选项

| 选项 | 说明 |
|---|---|
| `--from N --to M` | 只下指定章节区间 |
| `--workers N` | 并发数，默认 3，最大 8 |
| `--fresh` | 忽略缓存重下 |
| `--debug` | 出错时打印堆栈 |

## 追更

桌面版点 `⟳ 追更`；命令行 `node fanqie.mjs update`；或双击 `追更.bat`（结果写 `logs/update.log`）。

行为：

- 已完结**且已下完**的书跳过
- 关了开关的书跳过
- 其余只下新增章节 + 之前失败的章节，已有的全部跳过
- 完成后自动刷新书架

### 每天自动追更（可选）

`Win + R` → `taskschd.msc` → 创建基本任务 → 每天 → 启动程序填：

```
D:\WorkBuddy\Lan-日常\outputs\fanqie-reader\追更.bat
```

勾选「不管用户是否登录都要运行」。若报 `node 不是内部或外部命令`，把程序改成 node 全路径、参数填 `fanqie.mjs update`、起始位置填脚本目录。

## 工作原理（为什么能看全文）

番茄没有官方开放平台。网上流传的「番茄 API 申请」文档是假的，接口不存在。

这个工具走的是 **App 客户端接口**：

1. 匿名注册虚拟设备（device_id / install_id）
2. `x-argus` / `x-ladon` / `x-khronos` 签名 + DH 密钥交换拿内容密钥
3. 正文 AES-256-CBC 解密 —— 解出来是明文，没有网页端那套 PUA 字体混淆
4. 锁章在 App 渠道同样返回全文（网页端无 SVIP 只有约 200 字试读）

签名与解密来自开源项目 [openfanqie](https://github.com/J3n5en/openfanqie)（MIT）。本工具在其上增加了：设备池轮换、断点续传/增量追更、书架系统、桌面应用、HEIC 封面转 JPEG、离线阅读器生成。

## 已知限制

- **单设备有配额**：实测一个虚拟设备累计约 100–180 次请求后，服务端返回 HTTP 200 + 空 body（静默拒绝，不是 4xx，极易误判成网络故障）。遇到就自动退役换新设备。实测 1928 章用 143 台设备、约 1 分 40 秒
- **App 接口会变**：番茄客户端更新后签名可能失效，需等 openfanqie 跟进
- **封面是 HEIC + 签名 URL**：只能原样 GET，改扩展名返回 403。本地用 libheif(WASM) 解码后转 JPEG，纯 JS，无需装系统组件
- **Node 18+**（实测 22.22 / 22.23 均可）

### 迭代时怎么保证没删功能

`baseline-guard.mjs` 是静态检查，不启服务，几秒跑完。它盯的是「能力还在不在」，不是「跑得对不对」——正确性由上面几个行为套件负责。

已接到两道关口：

1. `run-all.mjs` 最后一个跑，失败即整体失败
2. `.git/hooks/pre-commit` 提交前自动跑，不通过直接拒绝提交

守卫抓到破坏时的样子：

```
==================================================
 提交被拒绝：功能完整性检查未通过
==================================================
   ✘ removeBook 走回收目录而非 unlink
   ✘ removeBook 函数体内无 unlink
```

**有意删功能**（比如决定不再支持导出 TXT）：同步更新 `BASELINE.md` 和守卫脚本里的检查项，再提交。守卫拦的是「不知不觉删掉」，不是「不许改」。

确实要绕过：`git commit --no-verify`。但绕过前想清楚是哪一种情况。

### 启动失败怎么查

双击后没反应，先看 `logs/app.log`。启动器、监听端口、开窗结果、未捕获异常都会记在那里。
（早期版本父进程只盲等 900ms 就退出，子进程崩了也看不出来——现在会轮询等到服务真的能响应才退出，起不来就回退到当前进程直接跑，不会点了没反应。）

## 开发

```bash
npm install          # 装依赖（sharp 有原生模块）
npm test             # 跑全部测试；需要本机有 Edge
node fanqie.mjs app  # 前台起服务，方便看日志
```

仓库只含源码。`books/`、`covers/`、`.cache/`、`screenshots/`、`书架.html` 都在 `.gitignore` 里——这些是运行时产物，里面是书籍正文和个人书单，不该进版本库。所以新克隆下来这些目录是空的，`npm test` 会自动造一批测试数据填进去，不影响之后加真书。

`开始.bat` / `追更.bat` 通过 `.gitattributes` 固定为 CRLF。Windows 的 cmd 遇到 LF 换行的批处理会直接报错，这条不能省。
